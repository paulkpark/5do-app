# 인계 문서 — 5DO 소울코드 내 천궁도 리딩 서브탭

> 이 문서와 `engine/` · `ui/` 폴더를 5DO 레포를 다루는 Claude Code 세션에 그대로 넘기면 됩니다.
> 작성 시점: 2026-09. 대상: 5do.app PWA(React SPA) — 소울코드 모듈 내 서브탭으로 추가.

---

## 0. 한 문단 요약

기존 소울코드는 사주·별자리·스타시드를 묶어 가볍게 읽어주는 모듈입니다. 이번 것은 **전문 점성술 차트 리딩**으로, 성격이 다릅니다. 정밀 천체력으로 행성 위치·에센셜 디그니티·디스포지터·프로펙션까지 계산한 뒤 15개 항목으로 해석합니다. **소울코드를 건드리지 말고**, 소울코드 안에 서브탭을 하나 더 만들어 붙이는 것이 목표입니다. 한국어·영어 토글을 지원하고, 해석 생성은 **유료 구독자에게만** 열립니다.

---

## 1. 무엇이 들어 있나

```
engine/                계산 + 프롬프트. UI·프레임워크 의존성 없음
  core.js              사인·디그니티 테이블, 어스펙트 탐지, 패턴, 디스포지터, 균형
  chart.js             차트 조립 + 타이밍(프로펙션·솔라리턴·프로그레션·트랜짓)
  i18n.js              모든 표시 문자열 (ko / en). 언어 추가 = 여기에 블록 하나 추가
  prompts.js           점성가 페르소나 + 15개 섹션 과제 + 모델용 차트 직렬화
ui/                    프레임워크 없는 참조 UI. React로 옮기든 그대로 쓰든 자유
  app.js               마운트·상태·섹션 렌더·구독 게이트
  wheel.js             천궁도 SVG
  places.js            내장 출생지 DB (한국 90여 곳 + 세계 주요 도시)
  geocode.js           지명 → 좌표 검색 (Open-Meteo / Claude 두 가지 구현)
  styles.css           다크 테마 스타일
demo/                  동작 확인용 번들 (esbuild)
```

### 설계 원칙 — 이것만은 지켜주세요

**엔진은 키만 뱉고, 표시 문자열은 i18n이 붙입니다.** `core.js`와 `chart.js`는 `'capricorn'`이 아니라 사인 인덱스 `9`를, `'도미사일'`이 아니라 `'domicile'`을 반환합니다. 언어를 바꿔도 **차트를 다시 계산할 필요가 없습니다** — 라벨만 다시 붙이면 됩니다. 이 경계를 깨고 엔진 안에 한국어를 넣으면 영어 지원이 즉시 깨집니다.

**계산은 코드가, 해석만 모델이 합니다.** 프롬프트에는 이미 계산이 끝난 표를 통째로 넣고 "다시 계산하지 말라"고 못 박습니다. LLM이 점성술에서 가장 많이 틀리는 지점이 행성 위치 추정이라서, 이 분리가 품질의 핵심입니다.

## 2. 붙이는 위치

소울코드 컴포넌트 내부에 탭을 하나 추가합니다.

```
소울코드
 ├─ 사주        (기존)
 ├─ 별자리      (기존)
 ├─ 스타시드    (기존)
 └─ 천궁도 리딩  ← 신규
```

별도 라우트로 빼지 않는 이유는, 출생정보(생년월일시·출생지)를 소울코드가 이미 받아두고 있기 때문입니다. **기존 프로필의 출생정보를 그대로 받아 입력 폼을 건너뛰는 것을 1순위로 해주세요.** 출생지가 좌표로 저장돼 있지 않다면 그때만 폼을 띄웁니다.

```js
import { setEphemeris, build, timing } from './engine/chart.js';
import { mount } from './ui/app.js';
import * as CNH from 'circular-natal-horoscope-js';

setEphemeris(CNH);
const chart  = build({ year, month, date, hour, minute, lat, lon, placeLabel, timeUnknown });
const timing_ = timing(chart, new Date());
```

기존 `astro-events.js`와의 관계: 그쪽은 **당일 천체 이벤트**(달 위상, 수성 역행 등)를 다루고, 이 엔진은 **개인 출생차트**를 다룹니다. 겹치지 않으니 양쪽 다 두시면 됩니다. 다만 데일리 레조넌스가 오늘의 행성 위치를 쓴다면 `chart.js`의 `rawPositions()`로 통일하는 편이 정확합니다 — 검증된 천체력이고 astronomy-engine과 0.01° 이내로 일치합니다.

## 3. 번들 크기 — 반드시 처리할 것

`circular-natal-horoscope-js`는 **765KB(min)** 입니다. 대부분 moment-timezone 데이터고, 이 덕분에 위경도만으로 과거 서머타임(한국 1948년, 1987~88년 포함)까지 정확히 처리됩니다. 정확도를 위해 치를 값입니다.

**메인 번들에 절대 넣지 마세요.** 서브탭을 열 때만 동적 로드합니다.

```js
const [engine, setEngine] = useState(null);
useEffect(() => {
  if (tab !== 'natal') return;
  Promise.all([
    import('circular-natal-horoscope-js'),
    import('./engine/chart.js')
  ]).then(([cnh, chart]) => { chart.setEphemeris(cnh); setEngine(chart); });
}, [tab]);
```

로딩 중에는 스켈레톤을 띄웁니다. 5DO는 PWA라 첫 진입 번들이 커지면 체감이 바로 나빠집니다.

## 4. 구독 게이팅

### 경계

| | 무료 | 구독자 |
|---|---|---|
| 차트 계산·천궁도 휠 | ✅ | ✅ |
| 데이터 표 4종 (천체/하우스/어스펙트/균형) | ✅ | ✅ |
| 섹션 2~15 AI 해석 | ❌ | ✅ |
| 심층 모드(Opus) | ❌ | 옵션 |

무료로 차트와 표를 다 보여주는 게 핵심입니다. 표가 충분히 전문적이라 그 자체로 "이 앱 제대로 만들었네"라는 신호가 되고, 그 상태에서 해석이 잠겨 있으면 전환 동기가 생깁니다. 차트조차 안 보여주면 그냥 이탈합니다.

### 연결

`ui/app.js`의 `mount()`에 entitlement를 넘기면 됩니다.

```js
mount(el, {
  lang,
  sample,
  entitlement: {
    canRead: featureFlags.natal_reading === true,   // 기존 feature_flags 사용
    onUpgrade: () => showUpgradeSheet('natal_reading')
  },
  loadCached, saveCached
});
```

`canRead: false`면 생성 버튼이 전부 사라지고 업그레이드 블록이 뜹니다. 차트와 표는 그대로 보입니다.

### 서버에서도 막을 것

클라이언트 플래그는 UI일 뿐입니다. `/api/reading` 핸들러에서 **세션 토큰을 검증하고 구독 상태를 다시 확인**해야 합니다. 이걸 빼면 무료 사용자가 API를 직접 호출해 과금시킬 수 있습니다.

## 5. 비용 — 캐싱이 핵심입니다

리딩 1건(14개 섹션)은 Sonnet 5 기준 **약 $0.4**입니다. 무제한으로 열면 구독료를 잠식합니다.

**결정적인 사실: 출생차트는 평생 변하지 않습니다.** 섹션 2~13, 15는 한 번 생성하면 영원히 유효합니다. 재생성할 이유가 없습니다.

```sql
create table natal_readings (
  id           uuid primary key default gen_random_uuid(),
  user_id      uuid not null references profiles(id),
  chart_key    text not null,     -- 년|월|일|시|분|위도|경도|시각미상
  lang         text not null,     -- 'ko' | 'en'
  section      int  not null,     -- 2..15
  body         text not null,
  model        text not null,
  created_at   timestamptz default now(),
  unique (user_id, chart_key, lang, section)
);
```

이 구조면:

- **섹션 2~13, 15** — 영구 캐시. 유저당 차트당 언어당 1회만 과금.
- **섹션 14(타이밍)** — 프로펙션·트랜짓이 바뀌므로 **월 1회 정도 재생성 허용**. 나머지 13개보다 훨씬 쌉니다.
- **언어 전환** — ko와 en은 별도 생성이므로 비용도 2배. 양쪽 다 미리 만들지 말고, 유저가 그 언어로 열 때만 생성하세요.
- **차트 개수 제한** — 본인 외에 가족·지인 차트를 무한정 만들면 비용이 선형으로 늘어납니다. 구독자당 **3개 정도**로 제한하고, 추가는 별도 과금이나 상위 플랜으로 두는 걸 권합니다.

이렇게 하면 구독자 1인당 실질 비용이 대략 **$0.4 × 차트수 × 언어수 + 타이밍 갱신분**으로 고정됩니다.

`loadCached(chartKey, lang)` → `{2: '...', 3: '...'}`, `saveCached(chartKey, lang, n, text)` 두 콜백만 구현하면 UI가 알아서 캐시를 씁니다.

## 6. API 프록시

기존 `akashic-frequency/api.js`가 이미 Claude 프록시 역할을 하고 있으니 **재사용하세요.** 새로 만들 필요 없습니다. 필요한 것은:

- `stream: true` 지원 (SSE 패스스루) — 섹션 하나가 1,000자 이상이라 스트리밍 없으면 체감이 나쁩니다
- `content_block_delta` 중 `delta.type === 'text_delta'`만 취할 것 (Sonnet 5는 adaptive thinking이 기본 on이라 thinking 블록이 섞여 옵니다)
- 모델: 기본 `claude-sonnet-5`, 심층 모드 `claude-opus-5`
- Sonnet 5는 **비기본 샘플링 파라미터를 거부**합니다. `temperature`, `top_p` 등을 넣지 마세요
- `max_tokens`는 thinking 몫까지 고려해 8000 이상

참조 구현이 필요하면 이전에 만든 Netlify 버전(`natal-reading-netlify.zip`)의 `netlify/functions/reading.mjs`를 보면 됩니다. 로직은 동일합니다.

## 7. 언어 토글

`ui/app.js`가 우상단에 토글을 그리고, `setLang(lang)`로 전환합니다. 5DO에 전역 언어 설정이 이미 있다면 그쪽에 종속시키고 이 토글은 감추세요 — `mount()`에 `lang`을 넘기고 `onLangChange`로 호스트에 알리면 됩니다.

번역 시 주의할 점 두 가지:

- **점성술 용어는 음역이 표준입니다.** 한국 점성술계에서 domicile은 "본거지"가 아니라 "도미사일", trine은 "삼분각"이 아니라 "트라인"으로 씁니다. i18n.js가 그 관행을 따르고 있으니 임의로 "순화"하지 마세요.
- **프롬프트는 언어마다 별도로 작성돼 있습니다.** 번역이 아니라 각 언어로 쓴 원문입니다. 영어 리딩을 한국어 프롬프트로 뽑으면 문체가 무너집니다.

## 7.5 출생지 검색 — 라이선스 확인 필요

지명만 입력하면 좌표를 찾아옵니다. 3단계로 동작합니다.

1. **내장 목록** — 즉시 표시. 한국 주요 도시와 세계 주요 도시. 오프라인에서도 동작
2. **지오코더** — 380ms 디바운스 후 호출. `"Greenville, NC"`처럼 쉼표 뒤에 주·국가를 붙이면 동명 지역이 걸러집니다
3. **좌표 직접 입력** — `"35.61, -77.37"` 형식을 감지

좌표가 정해지면 시간대는 위경도에서 자동으로 역산됩니다(과거 서머타임 포함). 별도 입력이 필요 없습니다.

`mount()`에 `geocode` 콜백을 넘기면 됩니다. 없으면 내장 목록 + 직접 입력만 동작합니다.

```js
import { openMeteoGeocoder } from './ui/geocode.js';
mount(el, { geocode: openMeteoGeocoder({ endpoint: '/api/geocode' }), ... });
```

### ⚠ 반드시 확인할 것

참조 구현은 Open-Meteo 지오코딩 API(GeoNames 데이터)를 씁니다. **API 키가 필요 없는 대신 무료 사용은 비상업 용도로 한정됩니다.** 5do.app은 유료 구독 제품이므로 그대로 쓰면 안 됩니다. 셋 중 하나를 골라야 합니다.

1. Open-Meteo 상업용 플랜 구독
2. 그들의 오픈소스 지오코딩 바이너리를 자체 호스팅 (GeoNames 덤프 기반, 서버 1대면 충분)
3. 다른 제공자로 교체 (Google Geocoding, Mapbox 등 — 키 필요, 유료)

어느 쪽이든 **자체 백엔드 프록시를 두는 편이 낫습니다.** 같은 출처라 CORS가 없고, 결과를 캐시하면 같은 도시 반복 검색에 비용이 들지 않으며, 제공자를 바꿀 때 클라이언트를 건드릴 필요가 없습니다. 캐시 키는 `지명|언어`면 충분합니다.

정확도 기준: 도시 중심 좌표면 충분합니다. 경도 0.05° 오차는 상승점을 약 12초각 움직이는 정도라 해석에 영향이 없습니다.

## 9. 알려진 한계 — 마케팅 문구에 반영할 것

- **주노·에로스·프시케 미포함.** 소행성 천체력이 없습니다. 프롬프트에서 모델이 값을 지어내지 못하게 막아뒀습니다. 필요하면 별도 천체력을 붙여야 하고, 그 전까지는 "미포함"으로 정직하게 표기됩니다. 카이런·릴리스·노드는 포함됩니다.
- **출생시각 미상 시 하우스 해석 불가.** 정오 가정 + 경고.
- **점성술은 검증된 예측 과학이 아닙니다.** 5DO는 이미 주파수 쪽에서 표현 규제 이슈를 다루고 있으니 같은 기준을 적용하세요. 화면 하단 고지를 지우지 마시고, 의료·재무 판단 근거로 쓰지 말라는 문구를 유지해야 합니다. 특히 영어판은 북미 시장을 향하므로 FTC 기준에서 "진단·치료" 뉘앙스가 들어가지 않도록 주의가 필요합니다.

## 10. 결정이 필요한 항목 (Paul 대표님 판단)

1. 구독자당 차트 개수 제한 — 3개? 무제한?
